1. The short version

A category has two parts: a tier (Low, Medium, High) and a level (1, 2, 3).

  • Level = how many of the three core modules the client bought: Community Development, Business Management, Environmental Health.
  • Tier = how big and involved the deal is, from up to six measurements: how many products, how many dollars, how many add-on product lines, and (where the data exists) how many integrations, how much data conversion and how much customization.
Client or city size (population) is not used anywhere. Confluence has no population field. Contract dollars are the only stand-in for size, and they measure the deal, not the jurisdiction.

2. Level: the three core modules

LevelRule
1One core module, or none listed (a project always has at least one, so an empty or add-on-only product list is assumed to be level 1)
2Exactly two of the three core modules
3All three core modules

Each core module counts once, however many products belong to it. These product names count toward a core module:

3. Tier: small, medium and large

Each project gets up to six scores from 0 (small) to 2 (large). Large always means score 2. A measurement with no data is skipped, not scored as zero.

MeasurementWhat is measured0 = small1 = medium2 = large
ScopeTotal number of contracted products (every product on the project page, including portal and add-on products)
ValueServices $ plus SaaS $ from the contract field. License, maintenance and add-on-management amounts are not included.
ComplexityNumber of add-on product lines (section 4), not counting the three core modules
Integrations*Distinct integration points: Tyler-to-Tyler integrations (e.g. ERP, Cashiering, Payments, Socrata), third-party integrations, third-party plan-review tools (e.g. BlueBeam, digEplan), and third-party payment or document-management APIs
Data conversion*Number of modules with data conversion (e.g. "BM - Data Conversion", "CD - Data Conversion"). "None" is a real zero.
Customization*Number of custom form or report development items (e.g. Tyler Civic Dev or ERP Dev contract, third-party forms). "None" is a real zero.

* Integrations, data conversion and customization are scored only when the dashboard's data source has them. Today that is the SharePoint-based Microsoft dashboard (Central Project Portfolio list). The Confluence dashboard's project pages do not contain these fields, so it skips them.

Complexity adjustments: on-prem or self-hosted adds one step (to a maximum of 2). A project whose title contains P2, Phase 2 or Add-on subtracts one step (to a minimum of 0).

Turning scores into a tier: average the scores the project has data for.

Average scoreTier
Low
Medium
High

Examples: scores of 2, 0, 0 average 0.67 and are Low. 2, 2, 0 average 1.33 and are Medium. 2, 2, 1 average 1.67 and are High. With six scores of 2, 2, 2, 1, 1, 1 the average is 1.5 and the tier is High.

"Large" is not one thing. A High project is usually large on two or three of the measurements, not necessarily on contract dollars. A $165K contract with 13 products and 6 add-on lines scores 1 + 2 + 2 = 5 and is High. A $500K contract with 6 products and no add-on lines scores 2 + 1 + 0 = 3 and is only Medium.

Where the dollar and count cutoffs came from: they were set to split this portfolio's own projects roughly into thirds (216 projects with a parseable dollar value had a median of about $260K). They are not an industry standard. They live in one place in the code and can be changed.

6. When data is missing

SituationWhat happens
No usable contract dollars (blank, "XX", ambiguous)The Value score is skipped; the tier uses the other scores.
Integrations, conversion or customization left blankThat measurement is skipped (unknown). Only an entered "None" counts as a real zero.
No products listedScope and Complexity are skipped; level is assumed to be 1.
No products and no dollarsShown as Unclassified until someone sets a category by hand.
Category set by handShown with a pencil mark; the automatic result stays visible in the hover text. Hand-set categories are kept when data is refreshed.

8. What the model does not use

  • City, county or client population, or number of users
  • Data conversion volume (records), or how complex each integration or customization is: only counts of them are used
  • Integrations, conversion and customization on dashboards whose data source does not have those fields (Confluence)
  • Customer readiness or how fast the client makes decisions
  • Region, state, project manager, or project health

These are real drivers of schedule. Adding any of them needs a new field on the Confluence page (or a manual input).
