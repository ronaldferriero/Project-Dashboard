# CRM ARR on Active Projects Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show each active project's client Total ARR and EPL ARR from Dynamics on the Active Projects page, with Snapshot tiles and an ARR by Region chart, refreshed by a weekly change-check job.

**Architecture:** A small Python Foundry agent client (ported from Analyst CoPilot) sends strictly read-only, single-tool prompts to the "EPL Support Agent (Test)" and parses the JSON in its streamed reply. A fetcher resolves Account Numbers to CRM accounts, sums customer product item ARR (all divisions and EPL only) in code, and keeps a local, git-ignored store plus a change log. A launchd job runs the weekly change check. The browser loads a JS wrapper of the store; a pure `CrmArr` module computes cells, roll-ups and chart rows, and `app.js` renders them only in Active mode when data exists.

**Tech Stack:** Python 3.12 + `requests` (already in `requirements.txt`), `unittest`; vanilla JS, Node `vm` tests (same style as `tests/test_changes_ui.js`); zsh scripts; macOS launchd; Tyler Forge 3.15.2 CSS.

**Spec:** `docs/superpowers/specs/2026-11-04-crm-arr-design.md` (read it before starting any task).

## Global Constraints

- Read-only against CRM, always. Every prompt starts with `AGENT_READ_ONLY` (exact text below), names exactly one read tool call, and says not to call any other tool.
- `AGENT_READ_ONLY = "READ-ONLY REQUEST. Use only read tools. Never call any create, update, resolve, escalate, assign, publish, or note tool, and never send communication."`
- Foundry defaults: base URL `https://foundry.tylertechai.com`, tenant `dev` (header `X-Tenant-Slug`), agent id `754773e3-5009-4a52-851d-14a1688c2a90`, endpoint `POST {base}/api/agents/{agentId}/stream`, auth header `X-API-Key`. Env overrides: `FOUNDRY_BASE_URL`, `FOUNDRY_TENANT`, `CRM_AGENT_ID`, `FOUNDRY_API_KEY`.
- Key fallback: if `FOUNDRY_API_KEY` is unset, read only `FoundryAPIKey` from the file at `ANALYST_COPILOT_ENV` (default `~/Tyler_Codex_Projects/Analyst CoPilot/.env`). Placeholders `<...>` and `replace-me` count as unset. Never log, store or send the key to the browser.
- EPL division label: `Enterprise Permitting & Licensing` (compare after `html.unescape` + `casefold` + whitespace collapse).
- Only Python's arithmetic produces totals; the agent never sums.
- Unmatched projects show `n/a`, never `$0`. Blank item amounts count as `0`.
- CRM files live only in `dashboard/data/crm/` (git-ignored). Nothing CRM-related is committed, published or pushed.
- The dashboard must look and behave exactly as today when `window.CRM_ARR_DATA` is absent.
- Colors only from `--forge-theme-*` tokens or existing token-mapped variables in `dashboard/styles.css`.
- Schedule: Saturday 06:00 local; catch-up when the last successful weekly check is older than 8 days; monthly reconcile on the first weekend (day 1-7, Saturday or Sunday).
- Existing suites stay green: `python3 -m unittest discover -s tests -p 'test_*.py'` (the 2 known upstream failures in `test_change_report.py` excepted) and `node tests/<each>.js`.

## Review Focus

1. Two runs at once (launchd job + catch-up + manual): the second waits or exits cleanly; the store is never half-written. Test in Task 3 (`test_lock_prevents_second_writer`, `test_save_is_atomic`).
2. Agent replies with prose, a truncated JSON block, or fewer rows than it said: that account becomes `error` with the reason, and its previously stored good values are kept, never replaced by 0. Test in Task 4 (`test_bad_reply_keeps_previous_values`).
3. Foundry fails mid-run (401, timeout): accounts finished before the failure are saved, the rest keep their old values, the process exits non-zero, and `refresh_dashboard.sh` still serves the page. Test in Task 4 (`test_http_failure_mid_run_saves_progress`) and Task 5 verification.
4. Division label arrives as `Enterprise Permitting &amp; Licensing`, different case, or extra spaces: still counted as EPL. Test in Task 4 (`test_epl_division_matching_is_tolerant`).
5. Amount arrives as `"$120,000.00"`, `"120000"`, `null`, or a number: parsed correctly, blanks count as 0. Test in Task 4 (`test_amount_parsing`).

### Task 6: Browser logic module `CrmArr`

Pure functions, no DOM, loaded before `app.js`.

**Files:**
- Create: `dashboard/crm-arr.js`
- Test: `tests/test_crm_arr.js`

**Interfaces:**
- Produces global `CrmArr` (same pattern as `PeerModel` in `dashboard/peer-model.js`):
  - `accountNumberFromTitle(title) -> string | null` (same regex as Task 3)
  - `hasData(data) -> boolean` (object with non-empty `accounts`)
  - `entryForRow(row, data) -> { status, total, epl, reason }` where `status` is `"ok"`, `"not_found"`, `"ambiguous"`, `"error"`, `"no_number"` or `"not_fetched"`; `total`/`epl` are numbers only for `"ok"` (and for `"error"` entries that still carry previous values), else `null`; `reason` texts: `"No account number in project title"`, `"Account <n> not yet fetched from CRM"`, else the stored `reason`
  - `sortValue(row, data, key) -> number | null` for keys `"crm_total_arr"`, `"crm_epl_arr"`
  - `rollup(rows, data) -> { total, epl, matched, projects, eplShare }` counting each Account Number once; `matched` = projects whose entry has numbers; `eplShare` = `epl / total` or `null`
  - `byRegion(rows, data, regionOf) -> [{ label, epl, other, total }]` sorted by `total` desc, each client counted once, assigned to the region of its first project in `rows` order; regions with `total === 0` omitted
  - `formatCompact(value) -> string` (`41800000` -> `"$41.8M"`, `612400` -> `"$612.4K"`, `950` -> `"$950"`)
  - `stampText(data, now) -> { text, warning }`: `text` = `"CRM ARR checked <Mon D, YYYY>"` from `last_weekly_check` (fallback `generated_at`); `warning` = `"weekly CRM check overdue"` when older than 8 days, else `"some accounts could not be refreshed"` when `last_run.errors > 0`, else `""`
